Main cost drivers in the current model are manual AP touches (recording invoice receipts, removing payment blocks, and clearing invoices) and a gating step (order confirmation) that can trigger avoidable coordination work. The redesign reduces labor-intensive steps and routes most cases through straight-through processing (STP) while keeping exception handling paths. Key changes and their cost impact: 
- Make Receive Order Confirmation non-gating and parallel: It remains optional but no longer delays downstream work. This avoids administrative follow-ups on confirmations for low-risk orders and removes waiting-driven handling costs.
- Enable automated invoice capture: Introduce an exclusive choice between Auto-Record Invoice Receipt (EDI) and manual posting. EDI invoices bypass manual entry, cutting AP effort per invoice.
- Prefer automatic clearing: Add an exclusive choice between Automatic Clear Invoice (STP) and an exception path. Most invoices will clear automatically, removing the manual clearing step cost.
- Isolate manual exception handling only when needed: Keep Remove Payment Block optional within the manual path before manual clearing. This ensures manual block removal happens only on blocked invoices, minimizing unnecessary touches.
- Keep the entire invoice process optional: For orders without invoices (e.g., free-of-charge items), the invoice handling chain is skippable, eliminating needless processing.
- Flatten and simplify control flow: Use a single top-level partial order and avoid nested partial orders as children of partial orders, improving maintainability without adding operational overhead.
These changes are feasible with standard capabilities: vendor segmentation for skipping confirmations, EDI for invoice auto-posting, three-way match configuration and tolerances for STP, and exception workflows for blocks. The result is fewer manual steps per case, reduced exception volume, and lower AP processing cost.
