Targeted improvements and how they achieve the goals:
- Prevent duplicate orders early: Added a pre-creation control activity “Check for Existing PO Item” and gated the whole PO process behind an exclusive choice. If a duplicate is detected, the process skips the entire PO creation and downstream steps. This prevents duplicate PO items at the source, avoiding downstream rework, cancellations, and invoice/payment corrections.
- Reduce execution cost via straight-through processing: Introduced “Auto 3-Way Match” between invoice receipt and clearing. When the 3-way match succeeds, the process goes directly to clearing; only in exceptions does it invoke “Remove Payment Block.” This reduces manual touches and exception handling effort.
- Better sequencing to maximize automation: Invoice processing is positioned after goods receipt and vendor invoice signaling, increasing the chance that the 3-way match finds all required references (PO, GR, IR), which in turn reduces the frequency of payment blocks and manual work.
- Keep non-value-adding steps optional: Kept “Receive Order Confirmation” optional so it does not add mandatory manual effort, contributing to cost reduction.
- Only execute invoice-related work when applicable: Wrapped the invoice processing subtree in an optional XOR, ensuring no invoice processing effort occurs if no invoice is received, cutting unnecessary activities.
Net effect: Fewer duplicate orders and reduced manual interventions (payment block removals), directly lowering processing cost while maintaining a feasible and standard P2P control flow.
