Targeted changes to reduce cost and prevent duplicate orders:
- Prevent duplicate orders before creation: Added a dedicated check step (Check Existing PO Item) followed by an exclusive choice between linking to an existing PO item or creating a new one. This stops duplicates at the source by routing duplicates to Link to Existing PO Item instead of creating another PO line.
- Quality gate with rework loop: After Create Purchase Order Item, introduced a validation-and-correction loop (Validate PO Item with an Amend PO Item redo). This ensures any duplicate or data-quality issues are fixed in-place rather than re-creating items later, preventing duplicates and rework cost.
- Cheaper order confirmation: Replaced the purely manual order confirmation with an XOR that includes Auto-Receive Order Confirmation, enabling automated confirmations when available and reducing manual effort.
- Straight-through invoice handling: Inserted a 3-way Match gate. If matching succeeds, we follow the Automatic Clear Invoice path; otherwise, we go through Remove Payment Block -> Clear Invoice. This concentrates manual work on true exceptions and reduces overall touch time.
- Lower-cost alternative to invoicing: Added an ERS option (Perform ERS Settlement) as an alternative to classical invoice processing. This bypasses vendor invoice creation/receipt and manual clearing, cutting processing cost where commercial terms allow.
- Preserved safe sequencing: Invoice processing is still downstream of goods receipt, and exception handling remains available. Concurrency of goods receipt with vendor invoice creation is retained to avoid idle time while not inflating cost.
These design changes directly reduce manual touches (automation, ERS, exception-only reviews) and systematically prevent duplicate order creation (pre-check plus validation loop), achieving both target goals.
