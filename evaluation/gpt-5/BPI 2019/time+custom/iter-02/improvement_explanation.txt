- Added pre-creation duplicate prevention: Introduced Acquire Creation Lock and Check for Duplicate PO Item, followed by an exclusive choice between creating a new PO item or linking to an existing one. The lock prevents race conditions where two parallel instances could both create the same PO item, and the duplicate check routes duplicates to the link path instead of creating a new order. This directly prevents duplicate orders.
- Shortened the critical path via concurrency: Removed the dependency that forced waiting for Receive Order Confirmation before continuing. After the creation/link decision, Record Goods Receipt, Record Invoice Receipt, and (optionally) Receive Order Confirmation and Vendor creates invoice now run in parallel. This reduces end-to-end execution time by eliminating unnecessary waiting.
- Faster invoice settlement with an exclusive clearing decision: After both Record Goods Receipt and Record Invoice Receipt are completed (three-way match availability), the process takes an exclusive path (xor) to either Auto Clear Invoice (happy path) or the manual path Remove Payment Block -> Clear Invoice. This accelerates the majority of cases by enabling straight-through processing while retaining the manual path for exceptions.
- Clean POWL structure: A single top-level partial order coordinates all steps, using xor for the exclusive choices and xor(None, ...) for optional steps. The manual clear sequence is modeled as a submodel inside the clearing xor to keep the exclusivity intact.
These changes reduce cycle time by maximizing concurrency and enabling straight-through invoice clearing, and they prevent duplicate orders by introducing a lock and a pre-creation duplicate check with an exclusive link-or-create decision.
