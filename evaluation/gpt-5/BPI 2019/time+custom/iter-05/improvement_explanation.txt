Targeted improvements and how they achieve the goals:
- Prevent duplicate orders: Added an explicit pre-check gate (Check for Duplicate Order) followed by an XOR decision. If a duplicate is found, the process branches to Handle Duplicate Order and ends without creating a new PO item. Only when no duplicate is found does the process continue to create a new PO item. This eliminates duplicate PO item creation at the source.
- Reduce execution time via parallelization: Moved Receive Order Confirmation out of the critical path. After creating the PO item, order confirmation, goods receipt, and the supplier invoice path can proceed concurrently, avoiding unnecessary waiting.
- Earlier invoice handling: Record Invoice Receipt now depends only on Vendor creates invoice (optional) and can occur in parallel with Goods Receipt. This enables earlier processing of invoices, shortening overall lead time.
- Straight-through processing for clean matches: Retained Remove Payment Block as an optional step (xor(None, Remove Payment Block)). Clear Invoice is enabled after both Record Invoice Receipt (through the optional payment block) and Record Goods Receipt. When no block is needed, the process skips directly to clearing, accelerating clean cases while still enforcing proper controls.
- Clear, feasible control logic: Clear Invoice must occur after both invoice and goods receipt are available, ensuring proper three-way match without delaying earlier steps. The model avoids nested partial orders within partial orders and uses XOR and partial order composition in a way that remains implementable.
These changes reduce waiting and handoffs, speed up straight-through cases, and add a robust gate to prevent duplicate POs.
