Targeted improvements and their impact:
- Prevent duplicate orders at the source: Added a Run Duplicate Check right before any creation. Based on the result, we route via an exclusive choice to either proceed with the normal flow (creating a new PO item) or Update Existing PO Item and end the case. This explicitly stops the creation of a new order when a matching open PO exists, preventing duplicates and avoiding all downstream work for those cases.
- Remove a non-value-adding gate and run work in parallel: Receive Order Confirmation was previously in the critical path (between creation and all subsequent steps). It is now modeled as an optional, concurrent activity after Create Purchase Order Item. This eliminates unnecessary waiting and shortens cycle time.
- Enable earlier invoice handling and matching: Vendor creates invoice is optional and Record Invoice Receipt now directly depends on that event. Both Invoice Receipt and Goods Receipt can proceed independently after PO creation, allowing earlier availability of data and reducing idle time.
- Fast path for straight-through processing: Introduced Perform 3-Way Match. After the match, an XOR either clears the invoice immediately on a successful match (auto-clear path) or routes to exception handling (Resolve Invoice Discrepancy -> Remove Payment Block -> Clear Invoice). This skips Remove Payment Block for the happy path, reducing manual interventions and overall execution time.
- Structuring choices to remain feasible: The 3-way match only starts once both Goods Receipt and Invoice Receipt are available, ensuring correctness. Optional vendor invoice creation still allows early IR when applicable. The model uses a copy of Clear Invoice in the fast path to avoid structural reuse issues across XOR branches.
These changes collectively reduce end-to-end execution time by removing gating, increasing concurrency, and shortening the happy path, while explicitly preventing duplicate orders through a front-end check-and-route mechanism.
