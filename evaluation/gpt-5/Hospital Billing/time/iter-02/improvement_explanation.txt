Key changes to reduce execution time:
- Removed the gating of FIN by CHANGE DIAGN: In the original model, FIN (and also RELEASE/CODE OK) had to wait for CHANGE DIAGN. We allow FIN and RELEASE to start immediately after NEW, while keeping the constraint that CODE OK must follow CHANGE DIAGN if it happens. This reduces the critical path by starting FIN earlier.
- Decoupled BILLED from RELEASE: Previously, BILLED had to wait for the optional block containing both RELEASE and CODE OK. Now, BILLED depends only on FIN and (optionally) CODE OK, so it can start as soon as FIN and CODE OK are done, without waiting for RELEASE. This cuts waiting time when RELEASE is slow or not required for billing.
- Flattened and simplified structure to increase parallelism: We replaced nested partial orders with a single partial order for the main flow and used optional branches (xor) for activities that may be skipped. This makes concurrency explicit and avoids unnecessary synchronization points.
- Preserved feasibility and original optionality: DELETE remains an exclusive alternative after NEW; CHANGE DIAGN, RELEASE, CODE OK, and BILLED remain optional as in the original, but with leaner dependencies to minimize idle time.
Net effect: FIN can begin immediately, CODE OK can start as soon as CHANGE DIAGN completes (or immediately if it is skipped), and BILLED can be triggered as soon as FIN and CODE OK are complete, reducing overall throughput time on the predominant non-deletion path.
