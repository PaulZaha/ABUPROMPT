External quality hinges on delivering correct, consistent outputs to external stakeholders (e.g., patients, providers, payers). The original model allowed RELEASE and CODE OK to occur concurrently and made them optional, and it even allowed the entire process to be silently skipped after NEW. This risks releasing or billing unvalidated work, inconsistent outcomes, and poor traceability. The improved model enforces quality gates and clear sequencing: 1) It removes the silent skip after NEW, requiring a choice between DELETE or proceeding with processing. 2) It introduces a controlled validation cycle: CHANGE DIAGN can be repeated 0..n times, but each cycle must end with CODE OK. The cycle itself can repeat from 1..n, ensuring validation after any change and at least one validation even when no changes are needed. 3) It enforces the sequence CODE OK -> FIN -> RELEASE -> (optional) BILLED, so nothing reaches external parties before being validated and finalized. 4) It eliminates concurrency between FIN, RELEASE, and CODE OK, preventing premature or inconsistent external outputs. Together, these changes improve external quality by ensuring correctness, completeness, and consistency of released and billed work, while maintaining feasibility (no exotic constructs and only standard POWL operators).
