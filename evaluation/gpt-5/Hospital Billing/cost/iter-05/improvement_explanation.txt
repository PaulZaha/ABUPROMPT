Cost-reduction-focused redesign decisions and their impact:
- Gate billing-related work behind an explicit decision: Previously, CHANGE DIAGN, RELEASE and CODE OK could be executed even if BILLED would be skipped, causing unnecessary labor cost. We modeled an XOR that only executes the billing flow when billing is actually pursued; otherwise it skips the entire billing block after FIN. This prevents performing coding and releases on cases that will not be billed.
- Make prerequisites for billing mandatory and ordered: In the original model, RELEASE and CODE OK were optional and concurrent, and BILLED could happen even if they were skipped. We made RELEASE and CODE OK mandatory before BILLED and sequenced them (RELEASE -> CODE OK -> BILLED). This reduces rework and denial costs due to incomplete or premature billing.
- Finalize before coding to avoid rework: FIN was concurrent with RELEASE/CODE OK, which risks coding based on incomplete information and subsequent rework. We require FIN to precede the billing block, reducing costly recoding and verification loops.
- Only change diagnosis if billing proceeds: CHANGE DIAGN is now optional within the billing flow and precedes RELEASE. It is performed only when billing is chosen, eliminating unnecessary corrections on cases that will not be billed.
- Remove the post-NEW do-nothing path: After NEW, we now require either immediate DELETE or continue to processing. Eliminating the pure skip branch reduces overhead from idle items and follow-up housekeeping, aligning with a tighter intake policy that avoids creating records with no intent to process.
Together, these changes reduce manual effort (less unnecessary coding/release/diagnosis changes), lower rework/denial remediation costs by enforcing proper sequencing and prerequisites, and trim non-value-adding cases early through the DELETE branch.
