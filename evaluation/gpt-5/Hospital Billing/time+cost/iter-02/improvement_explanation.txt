Key issues in the original model increasing time and cost: (1) The top-level XOR allowed skipping all post-NEW work, leaving dangling cases; (2) FIN could occur before BILLED and even without RELEASE/CODE OK, causing rework and late corrections; (3) CHANGE DIAGN was not tied to CODE OK, so changing a diagnosis did not automatically trigger re-validation. Improvements implemented: (a) Replace the three-way XOR after NEW with an exclusive choice between DELETE and a processing path, ensuring each case is closed either by deletion or by processing; (b) Introduce a coding quality gate with a loop(code_ok, change_diagn) so any diagnosis changes automatically trigger a re-check, reducing downstream billing rejects and rework; (c) Keep RELEASE and the coding loop concurrent to reduce elapsed time, but constrain BILLED to occur only after both RELEASE and the coding loop are complete; (d) Move FIN after the billing decision, guaranteeing closure only after financial completion. Effects on goals: (i) Reduced execution time via safe concurrency (RELEASE in parallel with coding) and by removing idle/skip paths that create waiting WIP; (ii) Reduced execution cost by preventing premature billing and re-openings, cutting rework cycles, and ensuring that any diagnosis changes are handled before billing.
