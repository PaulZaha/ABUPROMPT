Key issues in the original model driving cost and external quality problems: (1) RELEASE and CODE OK were concurrent, leading to coding on unstable data and rework; (2) FIN could happen concurrently with upstream work, allowing premature closure; (3) BILLED was optional and could be reached without a proven quality gate; (4) The whole post-NEW flow could be skipped, creating dangling cases; (5) DELETE was mixed with other optional branches, delaying early-stop and incurring avoidable cost. Improvements implemented: (a) Early decision after NEW with xor(DELETE, process) to stop invalid cases immediately and avoid downstream cost; (b) Enforce a clear, sequential backbone: RELEASE -> CODE OK -> BILLED -> FIN to improve predictability and customer-facing quality; (c) Introduce a lean correction loop loop(do=CODE OK, redo=CHANGE DIAGN), which validates once, and only if needed triggers a diagnosis correction followed by re-validation. This minimizes unnecessary corrections while guaranteeing that any change is re-validated before proceeding; (d) Move FIN outside the branch so both DELETE and processed cases are consistently finalized, preventing premature or missing closures; (e) Make BILLED mandatory in the processing branch to avoid revenue leakage; non-billable or canceled cases are steered to DELETE. These changes reduce rework and exception handling (lower execution cost), while gating billing through CODE OK and sequencing after RELEASE improves first-pass accuracy, customer trust, and fewer post-billing disputes (higher external quality).
